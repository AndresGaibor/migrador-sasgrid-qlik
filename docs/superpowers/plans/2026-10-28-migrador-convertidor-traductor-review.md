# Plan de revisión del migrador, convertidor y traductor SAS → Talend

## Objetivo

Revisar el flujo implementado en el árbol de trabajo actual y construir un backlog de **300 mejoras candidatas**. Las 300 son elementos para validar y priorizar, no una cuota de cambios que se deban implementar. El sistema analiza SAS estáticamente y propone/aplica una especificación Talend; no es un conversor universal ni valida equivalencia por sí mismo.

## Restricciones

- No ejecutar SAS ni scripts importados; usar fixtures sintéticas y pruebas offline.
- No conectar a sistemas productivos ni ejecutar Jobs Talend como parte de esta revisión.
- No promover una propuesta a traducción segura sin evidencia semántica y prueba que la respalde.
- Mantener desconocidos como pendientes; no inventar componentes, propiedades, esquemas o valores.
- Preservar el trabajo local existente. No editar ni revertir cambios ajenos a una tarea aprobada.
- Tratar el parser, la construcción de IR, la traducción de expresiones, el planificador y la aplicación MCP como límites distintos.

## Método y criterios de registro

Cada entrada tendrá ID `MIG-###`, capa, archivo/símbolo, evidencia reproducible, tipo (`bug`, `seguridad`, `calidad`, `cobertura`, `UX`, `rendimiento` o `documentación`), impacto, confianza, coste, dependencias y criterio de aceptación. Marcar como `confirmada`, `hipótesis`, `duplicada`, `no aplica` o `requiere decisión`. No rellenar artificialmente un cupo: si una categoría no tiene candidatos suficientes, dejar el número pendiente y explicar por qué.

Prioridad: **P0** riesgo de datos/seguridad o resultado engañoso; **P1** fallo frecuente o bloqueo del flujo; **P2** mejora de calidad/cobertura; **P3** optimización o refinamiento. Cada lote de implementación debe poder probarse sin SAS productivo y debe cambiarse en commits atómicos solo cuando el usuario solicite commit.
